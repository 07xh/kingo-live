# kingo-live：连接安全与代码收敛审查（2026-11-13）

## 本轮改动

- qiangke/qk/net.py：学校连接默认使用系统信任链验证 TLS，禁止为远程目标显式关闭验证，非本机 HTTP 目标拒绝创建会话。
- qiangke/qk/adapters/base.py：将青果和正方的连接配置合并为公共构造器，减少不同默认值造成的漂移。
- qiangke/tests/test_pwd.py：删除真实凭据回归样本，换为虚构账号/密码固定测试向量。
- qiangke/tests/test_tls.py：新增安全默认值、本机 mock 例外和两个适配器的回归测试。
- .github/workflows/ci.yml：Ubuntu 和 Windows 上新增 qiangke 七个离线脚本检查，不访问真实教务系统。

## 三套实现的收敛边界

| 目录 | 当前定位 | 后续收敛方向 |
| --- | --- | --- |
| qiangke/ | 青果/正方适配器、零第三方依赖 CLI | 先统一登录和课程列表数据契约 |
| ncwu/ | 教务开课计划/窗口读取及独立命令脚本 | 按实际课程字段对齐只读输出 |
| kingo-live/ | 独立 HTTP 客户端与网络模拟、HAR 分析 | 保留请求预算和观测数据；先写兼容性测试再决定迁移 |

本轮已合并 qiangke 内部两份会话配置。跨三个目录的完整网络层合并尚未实施：Cookie 生命周期、请求体编码和错误分类不同，直接替换会带来回归风险。Windows GUI 的在线提交也仍未经过验收。

## 重要安全事项

此前测试文件提交过真实账号密码。当前版本删除了明文，但 Git 历史、克隆、缓存中可能仍有副本。账号所有者应尽快修改受影响的密码并检查复用情况。改写共享分支历史应独立评估，不能把当前文件已脱敏误称为历史数据已清除。

## 验收标准

CI 绿色只代表代码检查与本机 mock 测试通过，不等于校园生产环境实际登录或正式选课成功。离线测试不得使用真实账号。若远程 TLS 证书验证失败，应修复证书信任链，不允许静默绕过。
